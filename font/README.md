# PUA駒グリフ (開発中)

将棋駒を PUA (Private Use Area, `U+E000`–`U+E10D`) に割り当てた自作フォント用の
素材置き場。引き継ぎ仕様書 4-3〜4-6 節の方針に沿っている。

## 現状

- `svg/` に先手14種・後手14種、計28個の SVG を生成済み
- デザインはいらすとや「将棋駒34点セット」を参考にした、クリーム地・角を
  丸めすぎない五角形・明朝体のスタイルで確定(下記「デザイン仕様」参照)。
  まだ手描きの仕上げではなく、このスタイルに沿った機械生成のグリフ
- `../lib/renderer.rb` の `pua` テーマは、このコードポイント表と同じ規則
  (`SENTE_BASE=0xE000` / `GOTE_OFFSET=0x0100`) で実装済みなので、フォントさえ
  導入すればアプリ側の対応は不要

## デザイン仕様(確定)

`preview.html` の「イラスト調(色付き・丸み)試作」Q1(通常駒)/Q7(成駒)案を採用。

- 地色 `#f5e2b8`(クリーム)、縁 `#b9824a`(木の色)、縁の太さ 3px
- 五角形の角は丸めすぎない(半径4、ほぼ尖った形を保つ)
- 文字は明朝体(`Hiragino Mincho ProN` スタック)
- 通常駒の文字色は `#4a3016`(こげ茶)
- **成駒(と・成香・成桂・成銀・馬・龍)は文字色だけ `#c0392b`(赤)にする**。
  地色・縁は変えない
- 成香・成桂・成銀は「小さい"成"バッジ + 通常サイズの地の文字」方式
  (二文字を均等に積むと小さいサイズで読みにくいため)

## ファイル

- `generate_svg.rb` — 確定デザインで SVG 28個を `svg/` に生成するスクリプト
- `build_preview.rb` — `svg/` の中身と検討過程の試作案を読み込んでブラウザ確認用の
  `preview.html` を組み立てるスクリプト(A〜P案・Q1〜Q7案の比較セクションも残してある)
- `svg/<sente|gote>-<key>.svg` — 個々のグリフ(1グリフ1ファイル)
- `preview.html` — 生成物のプレビュー(要 `ruby build_preview.rb` で再生成)

## デザインを差し替える

1. `svg/sente-fu.svg` など、差し替えたいグリフと同じファイル名で SVG を上書きする
   - `viewBox="0 0 100 100"` を保つと他のグリフと比率が揃う
   - 後手版は `gote-<key>.svg` を個別に用意する(単純な180°回転で機械生成してもよいし、
     手描きで別グリフにしてもよい)
2. `ruby build_preview.rb` で `preview.html` を再生成して見た目を確認する

## 検討過程のメモ

デザインが固まるまでに比較した案。`preview.html` に比較セクションとして残してある。

- 絵柄の方向性: 当初は線画(輪郭のみ)だったが、いらすとや(irasutofree.com)の
  「将棋駒34点セット」イラスト(著作権の都合で素材そのものは使わない、雰囲気の
  み参考)を見て、クリーム〜薄茶色の暖色・イラスト調に転換。丸ゴシックも試したが
  最終的に明朝体に戻した
- バッジ/地の文字の書体は草書体系(Yuji Boku/Syuku/Mai)も試したが、最終的には
  通常の明朝体(Hiragino Mincho)を採用
- 成り駒の色分け方法(枠ごと赤にする案・文字だけ赤にする案)を比較し、
  「枠は変えず文字だけ赤」に確定

### 技術的な注意点(FontForge工程で対応が必要)

- 通常のOpenType/TrueTypeフォントは1グリフ=単色インクが基本のため、成駒のように
  「地色・枠は同じ、文字だけ赤」を1文字の中で両立するには **COLR/CPALカラー
  フォント**(レイヤーごとに色を持てる形式。FontForgeで作成可能だが手順は増える)
  が必要になる見込み。アプリの Renderer 側で ANSI 色を変える方式では、1文字全体
  が同じ色になってしまう(地色・枠だけ元の色に残せない)ため、この要件には使えない
- **保留**: 本物の「行書体」が欲しくなった場合、Google Fonts には行書体として
  明示されたフォントが無い。SCREEN/モリサワの商用フォント「ヒラギノ行書」
  (StdN W4/W8)は本物の行書体だが有料でこのMacには未インストール。FontForge
  工程(ブラウザのCSP制約を受けない段階)まで進んだ時点で、購入して字形の
  トレース元にするかどうかを改めて検討する

## 次の工程(未着手)

1. 必要なら SVG を微調整・手描きで仕上げる(現状は上記デザイン仕様の機械生成)
2. FontForge で SVG を読み込み、上表のコードポイントに割り当てて OTF/TTF を生成する
   - 成駒の赤字を反映するには COLR/CPAL カラーフォントとしての作成を検討する
   - SVG の `<text>` はそのままだとフォント側に文字として取り込まれない可能性があるため、
     取り込み時にアウトライン化(パス化)するか、FontForge 側で該当漢字のグリフを
     複製して五角形と合成する方法を検討する
   - 「本物の行書体」を使いたい場合はここで検討(上記「保留」参照)
3. macOS に Font Book 経由でインストールする
4. Ghostty / kitty / iTerm2 などで `ruby bin/flash_shogi --theme=pua` を実行して確認する

推奨ターミナル優先順位: Ghostty > kitty > iTerm2 > Terminal.app(補助的)。
